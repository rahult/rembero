# Guided Query Canvas

- **Scope and mode:** Keep the full specialized IDE as the `/playground` Operate surface,
  linked from the separate public marketing homepage.
- **Audience and job:** Database-literate developers who want to evaluate Rembero without
  first learning Datalog terminology. They insert data, inspect SQLite, run a prepared
  rule, then verify the result through proof and graph.
- **Primary action:** Complete the optional four-action path: Add data → Inspect SQLite →
  Run a prepared rule → Trace why. Experienced users can skip guidance and operate every
  surface immediately.
- **Proof and constraints:** The same browser-local SQLite database feeds tables, SQL,
  Datalog results, proof ladder, lineage, and query-scoped graph. Advanced rule editing,
  constraints, recursion, raw JSON, and build hashes disclose contextually.
- **Direction:** Guided Query Canvas, approved by delegated expert choice. Preserve the
  Proof Ledger palette and open IDE topology. The memorable moment is a single inserted
  row traveling through the lineage rail into a derived answer and its exact support.
- **Approved comp:** `.impeccable/mocks/guided-query-canvas.png`
- **Constraints:** Static deploy; same C extension statically linked into SQLite Wasm;
  no model, upload, server mutation, persistent graph, fake metrics, or invented claims.
- **Shipped progression:** Sample SQLite rows establish an immediate successful query; row
  insertion, table inspection, prepared Datalog, result selection, proof, and graph all act
  on the same reload-reset database. On mobile, running a rule advances Query → Proof.
- **Advanced disclosure:** SQL scratchpad, integrity-boundary explanation, recursive path
  example, raw JSON, build hashes, and compiled SQL stay behind local disclosures. Recursive
  rules identify the native fixpoint evaluator instead of claiming one compiled statement.
- **Preserve:** Amber only traces provenance; cobalt only marks action or active state;
  derived rows are never presented as stored facts; graphs always retain a textual list;
  browser-local runtime status stays visible.

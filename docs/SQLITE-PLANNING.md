# Schema-only SQLite Datalog planning

Rembero 0.37 makes SQLite Datalog routing and database dependencies inspectable before
execution. Planning validates syntax and schema inside a savepoint but never scans table
or view rows.

## Use

```bash
rembero sqlite-plan world.db \
  'colleague(X, Y) :- works_at(X, C), works_at(Y, C), X != Y.'
```

Library callers use `DatalogDatabase.datalogPlan(program)`.

## Result

```json
{
  "mode": "native",
  "executionBoundary": "sqlite_scalar",
  "inputKind": "rule_program",
  "result": {
    "predicate": "colleague",
    "variables": ["X", "Y"]
  },
  "derivedPredicates": [
    { "predicate": "colleague", "arity": 2, "recursive": false }
  ],
  "baseRelations": [
    {
      "predicate": "works_at",
      "arity": 2,
      "objectType": "table",
      "temporary": false,
      "columns": [
        { "name": "person", "declaredType": "TEXT", "hidden": 0 },
        { "name": "company", "declaredType": "TEXT", "hidden": 0 }
      ]
    }
  ],
  "nativeSql": "SELECT DISTINCT ...",
  "scansData": false,
  "bounds": { "ruleBytes": 65536, "baseRows": 100000 }
}
```

Raw relational and aggregate queries omit `result.predicate` and report their actual
binding variables. Multi-predicate dependency cycles are analysed transitively, so a
predicate is marked recursive even through another derived predicate.

## Schema boundary

Planning uses the same `PRAGMA table_xinfo` visible-column rule and arity validation as
portable execution. It identifies main or temporary tables and views, preserves generated
columns (`hidden` 2 or 3), and reports declared types without applying affinity to data.

Missing relations and arity mismatches fail exactly as execution would. `NULL`, BLOB,
unsafe integer, and non-finite row values do not fail planning because rows are never read;
they remain execution-time portable-boundary errors.

The savepoint guarantees one coherent schema view and uses the same rollback/release error
handling as portable queries.

## Native SQL and the two-engine boundary

One non-recursive native rule includes `nativeSql`, generated by the C extension's
`datalog_sql`. Recursive or multi-rule native programs still run through the native scalar
fixpoint but do not claim one SELECT. Portable plans never include native SQL.

Planning does not attempt to move negation, arithmetic, aggregation, raw conjunctions, or
multi-predicate fixpoints into C. Those semantics continue to use the mature portable
engine over a SQLite read snapshot, avoiding a second drifting rule implementation.

## Scope

Planning is schema validation, not cost estimation: it returns no row counts, selectivity,
SQLite query planner estimates, or timing claims. The reported limits are the adapter's
active hard boundaries, not predicted consumption.
